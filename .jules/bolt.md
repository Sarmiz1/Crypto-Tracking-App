## 2025-06-15 - Recharts ResponsiveContainer Overhead in Tables and Pure Sparklines
**Learning:** Recharts `<ResponsiveContainer>` inside table rows (e.g., `CustomTableBody`, `SpotTable`) introduces massive rendering and layout overhead due to creating a `ResizeObserver` for each row. By specifying exact width and height on `<LineChart>` directly, we bypass observer creation completely, preventing scroll lag and rendering bottlenecks. Additionally, strict purity linting blocks functions like `Math.random()` inside render paths or hooks like `useMemo`, requiring deterministic mock generators using stable mathematics like `Math.sin(index)`.
**Action:** Always avoid `<ResponsiveContainer>` in loops, lists, or table rows; instead, use explicit width/height dimensions on `<LineChart>`. Use index-based trigonometric functions (e.g., `Math.sin(i)`) to mock dynamic trend line data instead of `Math.random()`.
